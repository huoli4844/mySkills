# file2md 陷阱与事故记录

> 从 v2.0.0 迁移的经验，v3.0.0 仍需注意。

## DOCX 提取事故 (v2.0.0)

### 事故：空函数成功返回

`_legacy_extract_docx()` 在代码重构后被简化为 `pass`（空函数）。
所有执行后 `✅ DOCX 提取完成` 但无任何输出文件。空函数成功返回，用户无法察觉失败。
涉及 3 个独立会话均未发现此问题。

### 预防

任何出口工具函数不可留 `pass` + 注释"待完善"。至少应：
```python
raise NotImplementedError("XXX 尚未实现")
```
或打印告警：
```python
print("⚠️ 警告：XXX 未实现，将产生空输出")
```

## PDF 模式已知限制

### 1. 公式提取

PDF 中公式是渲染后的图片格式（非 LaTeX 源码，非 OMML），Docling 仅保留为图片占位符。

**解决方案**：改用 DOCX 源文件 + pandoc，公式保真度最高。

### 2. 图片哈希去重不足

同一图在不同页面以不同分辨率/压缩率嵌入 → SHA256 无法去重。

**解决方案**：需要感知哈希（pHash/dHash），当前不实现。

### 3. 双图题注粘连

Docling 将同一行上的两句话合并 → 题注包含额外文本。
如：`图3.2.2 机载雷达告警器中的全向比幅天线 图3.2.3 现代的全向比幅单脉冲系统结构`

**缓解**：`_caption_to_filename()` 的截断层 4（`图N.N.N` 前截断）可分离文件名，但正文显示的题注仍为完整两段文本。

### 4. SmartArt/嵌入式图表未提取为图片文件（v3.3.0 未处理）

Pandoc 在转换 DOCX 时，**仅提取嵌入式 PNG/JPEG/EMF 图片**。DOCX 中的 **SmartArt 图表**（如三要素示意图、流程图、组织结构图等）不会被提取为独立图片文件。这是 pandoc 的已知限制，非 file2md 可修复。

**表现**：
- 正文中保留 `图1-1电磁干扰三要素` 纯文本标题（图题）
- assets/ 目录中**无**对应图片文件
- 下游消费方（如 domain-book-wiki 概念生成）尝试引用该图时，无法使用 `![图](path)` Markdown 语法

**检测方法**（output MD 中有 `图X-X` 标题，但 assets/ 中无同名文件）：

```bash
grep -E '^图[0-9]+[-.][0-9]+' output.md | head
ls output/assets/ | grep -c '图[0-9]'  # 为0且有grep输出→SmartArt图未提取
```

**当前缓解**：
- domain-book-wiki v21.13 的 `figure_references` 生成规则已适配：图片文件存在时用 `![...](...)` 语法，不存在时用 `> blockquote` 文字说明+来源标注

### 5. 表格数据行可能为空

Docling 在复杂排版的中文教材 PDF 中可检测到表结构，但部分数据行内容为空。

**解决方案**：改用 DOCX 源 + pandoc 表格提取。

## DOCX 模式已知限制（pandoc 输出）

### 1. LaTeX 反斜杠被替换为 `/`

pandoc 将 `\frac` 输出为 `/frac`，`\{` 输出为 `/{` 等。
v3.0.0 通过 `_fix_pandoc_latex()` 三层策略修复。

### 2. 表格行间空行

pandoc 输出的 `|...|` 行之间有空行，GFM 渲染器不支持。
v3.0.0 通过 `_fix_table_blank_lines()` 修复。

### 3. ` ``` math ``` ` 格式不被渲染器支持

pandoc 特有的 ` ``` math ``` ` 格式不被大多数 Markdown 渲染器支持。
v3.0.0 将其转为 `$$...$$` 格式。

## 推荐工作流

| 获取方式 | 输出质量 | 适用场景 |
|:---------|:--------:|:---------|
| DOCX + pandoc | ⭐⭐⭐⭐⭐ | 有 DOCX 源时首选，公式/表格/格式全保真 |
| PDF + Docling | ⭐⭐⭐⭐ | 仅 PDF 可用，结构化理解+图片提取 |
