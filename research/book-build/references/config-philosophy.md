# 配置分层哲学（2026-06-12 确立）

## 核心原则：每层只放该层该管的事

```
book-build.yaml     → 项目元数据（教材名、参考书路径）
SKILL.md            → 通用写作规范 + 操作工作流
写作大纲（writing-guide-*.md） → 每章内容结构 + 章节特异规则
```

## 历史教训

最初尝试将写作风格规范放进 `book-build.yaml`（writing_style 块），用户两次纠正：

1. **第一次**：嫌太简单像检查表 → 重写为 7 个维度的"写作哲学"
2. **第二次**：要求全部移除 → 这些应该在各章写作大纲中定义

同期移除的还有：
- `knowledge_base` 块（冗余，`source_books[].path` 已覆盖）
- `density_baseline`（公式/例题/表格底线是章节特异性的）

## 判断标准

| 想放的内容 | 应放哪里 | 理由 |
|:----------|:---------|:-----|
| 教材名、提纲文件 | book-build.yaml | 项目级元数据 |
| 参考书路径和优先级 | book-build.yaml | 项目级配置 |
| 公式编号格式、案例真实性 | SKILL.md | 全书通用规则 |
| 操作工作流（P0/P1/扩充） | SKILL.md | 全技能通用流程 |
| 每章写哪些子节 | 写作大纲 | 章节特异性 |
| 该章建议体量/公式密度 | 写作大纲 | 章节特异性 |
| 该章写作风格侧重 | 写作大纲 | 章节特异性 |
| 具体数值/参数 | 写作大纲 | 章节特异性 |

## 检查清单

向 `book-build.yaml` 加内容前先问：

- [ ] 这是项目级配置还是章节级配置？
- [ ] 这条规则对全书 13 章都同等适用吗？
- [ ] 如果换一本教材（如"通信原理"），这条规则还适用吗？

只有三个"是"的，才放进 `book-build.yaml`。
