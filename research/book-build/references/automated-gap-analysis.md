# 大纲-章节差距自动化分析（Automated Outline-vs-Chapter Gap Analysis）

> **触发条件**：写作大纲已生成（`output/写作大纲/writing-guide-ch*.md`），已有章节正文（`output/第N章-*.md`），需要批量对比找差距。
>
> **输入**：项目根目录下的 `output/写作大纲/` 和 `output/` 中的章节文件。
> **输出**：`output/补充与完善分析报告.md` + `output/补充执行清单.json`。

## 自动化分析流程

```bash
# 从项目根目录运行
python3 ~/.hermes/skills/research/book-build/scripts/outline_vs_chapter_audit.py \
  --project "/path/to/项目目录" \
  --output "/path/to/项目目录/output"
```

## 分析维度

对每章并行执行以下检测：

| 维度 | 检测方式 | 阈值/判定 |
|------|---------|----------|
| **小节覆盖** | 从写作大纲提取 `### X.Y 标题`，在章节正文中搜索节号 | 未找到 → 缺失小节 |
| **案例数量** | `grep -c '\*\*案例\d+-\d+\*\*'` | < 2 → 不足 |
| **例题数量** | `grep -c '\*\*例\d+-\d+\*\*'` | < 2 → 不足 |
| **公式数量** | `grep -c '\\tag{'` | 0 → 警告 |
| **Mermaid图** | `grep -c '```mermaid'` | 0 → 警告 |
| **表格数** | `grep -c '^|[-\s|:]'` | 0 → 警告 |
| **章节小结** | 搜索 `本章总结` | 不存在 → 缺失 |
| **习题** | 搜索 `## 习题` | 不存在 → 缺失 |
| **军规未落实** | 从大纲中 `- [ ]` 标记的军规检查项 | 未打勾 → 未落实 |

## 输出格式

### 终端汇总表

```
章   | 大小KB   | 公式   | Mermaid | 表格   | 例题   | 案例   | 小结  | 习题  |  图表 
================================================================================
第1章 |     97.3 |   14 |       2 |    9 |    3 |    0 |   ✓ |   ✓ |    3
```

### 详细分析报告（Markdown）

按章输出：
- 当前内容统计（表格）
- 未覆盖小节列表
- 各节目标体量与覆盖情况
- 参考书盲区/可补充内容（从写作大纲提取）
- 综合建议（自动诊断）

### 执行清单（JSON）

结构化数据供后续脚本消费，每个 action 标记类型：
- `missing_section`: 缺失小节
- `missing_cases`: 案例不足
- `missing_examples`: 例题不足
- `missing_summary`: 缺章节小结
- `missing_exercise`: 缺习题
- `unmet_rule`: 军规未落实

## 执行优先级

**P0（结构性）**：缺失小节、缺章节小结、未撰写的章
**P1（质量性）**：案例不足、例题不足、参考书盲区补充
**P2（细节性）**：军规逐一落实、体量达标

## 补充写作阶段

对每个缺失项，进入 `content-supplementation-workflow` 的 Step 1-7：
1. 读取写作大纲中该节的 `必须包含的要素`
2. 搜索参考教材提取素材
3. 精确定位插入点
4. 用 `patch` 工具插入
5. 验证内容已插入
6. 处理编号连锁
7. 运行 `post_generation_check.py --fix`

## Pitfalls

1. **节号匹配**：大纲中 `### 1.4.5 分贝制详细讲解` 的节号是 `1.4.5`，在章节正文中搜索时要用节号字符串 `1.4.5`，不是标题文字。节号可能嵌套在 `####` 或 `**（6）**` 等不同格式下。
2. **体量目标解析**：大纲中的体量目标是 KB 单位（如 `38KB`），脚本会累加所有节的目标值。如果目标值为 0，说明大纲中未设置体量目标，不应用体量达标判断。
3. **军规检查项**：大纲中 `- [x]` 表示已落实，`- [ ]` 表示未落实。只报告 `未落实` 项。
4. **大文件读取**：章节正文可能很大（>100KB），检测时只用 `grep`/`re.findall` 等轻量操作，不要 `read_file` 整个文件。
5. **第14章拆分惯例**：某些项目中第14章（实验/案例章）不以章节正文文件存在，而是拆分为 `案例/` 和 `实验/` 子目录下的独立文件。分析时应排除第14章，避免误报"未撰写"。确认方式：检查 `output/案例/` 和 `output/实验/` 目录下是否有文件，若有则排除第14章。
6. **军规检查项格式**：大纲中 `- [x]` 表示已落实，`- [ ]` 表示未落实。只报告未落实项。部分章节的军规检查可能写在大纲末尾的文本块中，需用正则 `r'- \[ \]'` 匹配空方括号，不要匹配 `- [x]` 或 `- [X]`。

## 补充写作阶段优先级框架（P0/P1/P2）

对每章的差距按以下优先级排序执行：

| 优先级 | 类型 | 判定条件 | 典型项 |
|:------:|------|---------|--------|
| **P0** | 结构性 | 缺失小节、缺章节小结、未撰写 | 8个小节缺失、4章缺小结 |
| **P1** | 质量性 | 案例<2、例题<2、参考书盲区 | 13章无案例、11章无例题 |
| **P2** | 细节性 | 军规未落实、体量不足 | 58条军规细节 |

**执行原则**：P0 全部完成后再进入 P1。P0 完成后章节骨架完整；P1 完成后内容质量达标。

**注意**：第14章（实验/案例章）通常已拆分为 `案例/` 和 `实验/` 目录，分析时应排除，避免误报。
