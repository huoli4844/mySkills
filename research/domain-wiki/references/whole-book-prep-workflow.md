# Whole-Book MD Preparation Workflow

## When to Use

The input is a single `.md` file containing an entire textbook (generated by file2md or manual concat), not individual chapter files. This workflow splits it into the per-chapter `20_正文/` files that the standard domain-wiki pipeline expects.

## Architecture

```
raw/书籍名/                     ← READ ONLY — source files live here
  ├── 书籍名.md                 (整书 md, 10k-20k lines)
  └── images/                   (1237+ embedded images)

领域目录/书籍名/                 ← WORKING DIR — created by prepare step
  ├── 10_总揽/ 20_正文/ 30_核心概念/
  ├── 40_知识要素/ 50_知识点/ 60_技能点/
  ├── 70_应用场景/ 80_实体/ 90_习题/ 90_习题/解答/
  └── 20_正文/
      ├── images/               (copied from raw/ to preserve relative refs)
      ├── 第1章 绪论.md
      └── 第2章 ...
```

**Critical constraint**: `raw/` is read-only. Never write into `raw/`. The working book directory must be created parallel to `raw/` under the domain directory.

## Step-by-Step

### 1. Run prepare (creates dirs + copies images + splits chapters)

```bash
cd <domain-wiki-skill>/scripts
python3.12 split_book_to_chapters.py prepare \
  --raw-dir /path/to/kb/raw/书籍名/ \
  -w /path/to/kb/领域名/书籍名/ \
  --split
```

This single command:
- Creates 10_总揽, 20_正文, 20_正文/images, 30_核心概念, …, 90_习题/解答
- Copies all images from `raw/书籍名/images/` to `20_正文/images/`
- Scans the whole-book md for chapter headings → splits into individual files
- Standardizes filenames to `第N章 名称.md` format

### 2. Init pipeline (for each chapter)

```bash
python3.12 dag_controller.py pipeline init \
  -w /path/to/kb/领域名/书籍名/ \
  --book-id 01_书籍名 \
  -c 1
```

### 3. Standard DAG workflow continues

Agent writes YAML → `pipeline auto` → `pipeline batch` — same as the standard per-chapter workflow.

## Chapter Heading Detection

`discover_chapter_ranges()` auto-detects chapter boundaries using:

```python
CHAPTER_PATTERN = re.compile(r"^(#{1,2})\s*(第\s*\d+\s*章\s*.+?)(?:\s*$)")
```

This handles both `# 第1章` and `## 第 1 章` variants with arbitrary whitespace.

### TOC Deduplication

Many books contain two sets of chapter headings (TOC + body content). The algorithm groups by chapter number and keeps only the **last** occurrence (the body content version). Example: 工程电磁兼容第3版 had 26 raw headings → 13 content chapters after dedup.

### Filename Normalization

```python
# "第 2 章 电磁兼容基本概念…… 24" → "第2章 电磁兼容基本概念.md"
# "第1章 绪论" → "第1章 绪论.md"
```

Page-number suffixes (`…… 215`) and extra whitespace are stripped. The resulting filenames match `re.match(r"第(\d+)章\s.*\.md$", fname)` expected by `discover_chapters()`.

## Pitfalls

| # | Trap | Prevention |
|:--|:-----|:-----------|
| 1 | `raw/` is read-only but chapter files get written there | Always use `-w` pointing to the domain/book directory parallel to `raw/` |
| 2 | TOC headings (目录) and content headings both detected → duplicate files | Dedup by chapter number, keep last occurrence |
| 3 | Mixed `#` vs `##` heading levels | `CHAPTER_PATTERN` uses `#{1,2}` — covers both |
| 4 | Filename contains page numbers (e.g. ……215) → discover_chapters fails | `normalize_filename` strips `……\d+` suffixes |
| 5 | Image references broken after chapter split | Copy `raw/book/images/` to `20_正文/images/` — relative `![](images/xxx)` refs preserved |

## Commands Reference

| Command | Purpose |
|:--------|:--------|
| `split_book_to_chapters.py prepare --raw-dir X -w Y --split` | Full prep: dirs + images + split |
| `split_book_to_chapters.py split input.md -w Y` | Split only (dirs+images already exist) |
| `split_book_to_chapters.py prepare -w Y --raw-dir X` | Create dirs + copy images only |
