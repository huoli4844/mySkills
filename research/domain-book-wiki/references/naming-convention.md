# 命名规范 v18.0

## 概述

本文档统一定义 `domain-book-wiki` 技能中所有文件、目录的命名规范。其他文档应统一引用本文档。

## 1. 目录结构规范

### 四级目录树

```
wiki/
├── 00_知识库总控/                  ← L4 知识库级综合（跨领域）
│   ├── kb_overview_{kb_name}_0.md
│   ├── concept_index_{kb_name}_0.md
│   ├── knowledge_index_{kb_name}_0.md
│   ├── skill_index_{kb_name}_0.md
│   └── scenario_index_{kb_name}_0.md
│
└── 01_领域/
    ├── 00_领域总控/                ← L3 领域级综合（跨书籍）
    │   ├── domain_overview_{domain_id}_0.md
    │   ├── concept_index_{domain_id}_0.md
    │   ├── knowledge_index_{domain_id}_0.md
    │   ├── skill_index_{domain_id}_0.md
    │   └── scenario_index_{domain_id}_0.md
    │
    └── 01_资料库/
        └── {book_id}/             ← 单书目录
            ├── 10_总揽/           ← L2 索引（5个索引文件）
            ├── 20_正文/           ← 源文件MD
            │   └── assets/        ← 图片资源
            ├── 30_核心概念/       ← L1 核心概念（短名）+ 知识要素（短名）
            ├── 30_知识要素/       ← KE重定向目录（template_assembler输出）
            ├── 40_知识点/         ← L1 KP
            ├── 50_技能点/         ← L1 SP
            ├── 60_应用场景/       ← L1 scene
            ├── 70_实体/           ← L1 entities
            └── 90_习题/           ← L1 exercises
                └── 解答/          ← L1 solutions
```

### 编号体系

| 编号前缀 | 用途 | 逻辑分组 | 层级 |
|:---------|:------|:---------|:-----|
| `00_` | 知识库/领域总控（L3/L4） | 顶层索引 | L3/L4 |
| `01_` | 领域/资料库容器 | 容器目录 | L3 |
| `10_` | 单书总揽（L2索引） | 单书索引 | L2 |
| `20_` | 正文（源文件MD） | 原始资料 | L1 |
| `30_` | 核心概念 + 知识要素 | 概念系 | L1 |
| `40_` | 知识点 | KP | L1 |
| `50_` | 技能点 | SP | L1 |
| `60_` | 应用场景 | Scene | L1 |
| `70_` | 实体 | Entity | L1 |
| `90_` | 习题 | 练习系 | L1 |
| `解答/` | 习题解答（习题的子目录，无编号前缀） | 练习系-解答 | L1 |

编号跨度（30→40→50→60→70→90）保留中间空间，必要时可插入新节点类型而无需全局重编号。

## 2. 文件名命名规范（核心）

### 按节点类型统一规则

| 节点类型 | 文件名格式 | 示例 | 说明 |
|:---------|:----------|:-----|:------|
| **核心概念** | `{名称}.md` | `传导耦合.md` | 短名，书章信息在 frontmatter |
| **知识点（KP）** | `{名称}.md` | `传导耦合分析技术.md` | 短名 |
| **技能点（SP）** | `{名称}.md` | `能识别传导耦合路径.md` | 短名，推荐以"能"开头 |
| **应用场景** | `{名称}.md` | `PCB布线耦合分析.md` | 短名 |
| **知识要素（KE）** | `{名称}.md` | `传播常数.md` | 短名 |
| **实体** | `{名称}.md` | `麦克斯韦.md` | 短名 |
| **习题** | `{名称}_{书}_{章}.md` | `第2章-习题1_电磁兼容基础_2.md` | 长名。名称建议格式：`{章}章-习题{N}` |
| **习题解答** | `{名称}-解答_{书}_{章}.md` | `第2章-习题1-解答_电磁兼容基础_2.md` | 在对应习题名后加`-解答`，避免与习题文件同名 |

### 命名要素说明

- `{名称}`：节点名称，自动清理特殊字符（`\/:*?"<>|`）
- `{书}`：书籍简称（如 `电磁兼容基础`、`电子对抗原理与技术`）
- `{章}`：章节号（如 `2`、`3`、`8.1`），统一用阿拉伯数字
- 禁止使用 ID 前缀（如 `CONCEPT_001_名称.md`）
- **习题/解答**允许使用`第X章-`前缀（如`第2章-习题1`），这是名称的一部分，用于表达章节归属；其他类型不应使用章节前缀

### 多书模式下文件名

同名的概念/KP/SP/场景在不同书中通过目录路径区分：

```
wiki/01_领域/01_资料库/
├── 01_电磁兼容基础/30_核心概念/传导耦合.md
└── 02_电子对抗/30_核心概念/传导耦合.md
```

路径本身已唯一，文件名无需加书后缀。

## 3. Wikilink 格式规范

### 基本格式
```
[[路径/文件名|显示名]]
```
路径从 wiki 根开始。

### 各类型引用规则（当前单书目录结构）

| 引用目标 | Wikilink 格式示例 |
|:---------|:-----------------|
| 核心概念 | `[[30_核心概念/传导耦合|传导耦合]]` |
| 知识点 | `[[40_知识点/传导耦合分析技术|传导耦合分析技术]]` |
| 知识要素 | `[[30_核心概念/传播常数]]` |
| 技能点 | `[[50_技能点/能识别传导耦合路径|技能点名称]]` |
| 应用场景 | `[[60_应用场景/PCB布线耦合分析|场景名称]]` |
| 习题 | `[[90_习题/第2章-习题1_电磁兼容基础_2|习题1]]` |
| 习题解答 | `[[90_习题/解答/第2章-习题1-解答_电磁兼容基础_2|习题1解答]]` |
| 实体 | `[[70_实体/麦克斯韦|麦克斯韦]]` |
| 单书总揽 | `[[10_总揽/book_overview_01_电磁兼容基础_0|《电磁兼容基础》]]` |
| 领域总控 | `[[01_领域/00_领域总控/domain_overview_01_电磁兼容领域_0|电磁兼容领域]]` |
| 知识库总控 | `[[00_知识库总控/kb_overview_电磁兼容知识库_0|电磁兼容知识库]]` |

**规则**：
- 概念/KP/SP/场景 引用时不带书章后缀（短名）
- KE/实体/习题/解答 引用时必须带书章后缀
- 索引文件用长名（含 book_id / domain_id / kb_name）

## 4. Front Matter 字段规范

| 字段名 | 用途 | 适用类型 | 示例 |
|:-------|:-----|:---------|:-----|
| `name` | 节点名称 | 全部 | `传导耦合` |
| `type` | 节点类型标识 | 全部 | `concept` / `knowledge-element` / `knowledge` / `skill` / `scenario` / `entity` / `exercise` / `solution` |
| `type_tags` | 类型标签（12类） | 概念/KE/KP/SP/场景 | `["概念"]` |
| `book_id` | 书籍 ID | 全部 | `01_电磁兼容基础` |
| `book_name` | 书籍名称 | 全部 | `电磁兼容基础` |
| `chapter_num` | 章节编号 | 全部 | `2` |
| `confidence` | 置信度 | 全部 | `0.95`（概念）/ `0.65`（其他） |
| `confidence_note` | 置信度说明 | 全部 | `精准释义逐字匹配出处原文` |
| `source_chapter` | 来源章节 | 概念/KE | `第2章` |
| `source_from` | 来源正文 | 概念/KE | `传导耦合是指...` |

# 命名规范执行体系

## 三层校验架构

根据 `naming-convention.md`，所有节点类型使用短名 `{名称}.md`，仅习题/解答用长名 `{名称}_{书}_{章}.md`。

三层校验确保命名规范不被违反：

### 第1层：生成层（build_kb_files.py）

builder 函数不再自动添加 `第N章-` 前缀。`_chapter_prefix()` 函数已移除。
文件命名完全来自 YAML 数据中的 `file` 字段。

### 第2层：验证层（dag_controller.py verify()）

`dag_controller.py` 的 `verify()` 函数在 pipeline assemble 后执行：

- **short 类型**（概念/KP/SP/Scene/KE/Entity）：
  - 检查无 `第N章-` 前缀 → `⚠ [命名违规] 短名不应含章节前缀`
  - 检查无无效下划线 → `⚠ [命名违规] 短名含无效下划线`
- **long 类型**（习题/解答）：
  - 检查含 `_` 后缀 → `⚠ [命名违规] 长名缺后缀`

### 第3层：质量检查层（comprehensive-content-check.py）

独立质量检查工具 `comprehensive-content-check.py _scan_dir()` 对每个目录执行：

- short_types = {concept, knowledge, skill, scenario, knowledge-element, entity}
  - `第N章-` 前缀 → FAIL
- long_types = {exercise, solution}
  - 缺 `_` → FAIL

## 历史教训

- v26.0 之前：`build_kb_files.py` 为所有类型添加 `第N章-` 前缀，严重违反 naming-convention.md
- 已有文件重命名 78 个，发现 1 个 KE 同名冲突（电磁兼容预测基本方程同时出现于 ch1 和 ch3）
- 质量审查体系最初未检查文件名，导致违规范例长期未被发现
- 修复后三重校验体系确保命名规范被强制执行
