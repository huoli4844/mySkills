# Scene Solution Batch Generation Pattern (场景方案详解批量生成)

> v50.0: delegate_task 并行生成 9 个场景方案详解的经验固化。

## When to Use

需要为大量场景（≥3个）同时生成详细的工程方案详解内容时。

## Pattern

### 1. 分类场景

按现有内容质量分三类：
- **A 类**（已有详细案例）：只需格式转换（`【详细方案】` → `【方案详解】`），直接 `patch`
- **B 类**（有简要案例）：基于现有案例扩展为完整方案详解，`delegate_task`
- **C 类**（案例单薄）：完全新生成方案详解，`delegate_task` + 提供详细场景约束

### 2. delegate_task 并行策略

每批 3 个场景并行，传上下文给子代理。

### 3. Context 模板（关键——防子代理常见错误）

```
为「{场景名}」场景生成并写入【方案详解】。
场景文件路径: {绝对路径}
要求：参照参考场景格式，生成 5-6 个分项的详细工程方案。
每个分项含具体参数、选型和工程计算。
格式：【方案详解】\n一、xxx：...(含具体参数)\n...\nN、预期结果：...
完成后必须用 patch 工具将内容写入目标文件。
分项标题使用纯文本"一、xxx"，不使用 markdown 标题标记（#）。
```

### 4. 格式统一（三要求）

| 要求 | 正确 | 错误 |
|:--|:--|:--|
| 标题标记 | `【方案详解】` | `#### 【方案详解】` |
| 分项标题 | `一、xxx：...` | `##### 一、xxx` |
| 写入方式 | `patch` 写入文件 | 在 summary 中返回文本 |

### 5. 验证

```bash
grep -l "方案详解" 70_应用场景/*.md | wc -l    # 期望 10/10
```

## Pitfalls

- **P30**: 子代理约 17% 只返回文本不写文件 → context 中必须明确要求 patch
- **P31**: 子代理约 33% 格式不一致 → context 中明确纯文本标题格式
- 父代理收到 summary 后必须验证实际写入
