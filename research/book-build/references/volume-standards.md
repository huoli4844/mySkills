# 体量标准与12条写作军规清单

## 体量铁律

**每章字节数 ≥ 第1章字节数 × (5~10)**

这是硬性指标，写作前必须用 `wc -c` 验算：

```bash
ch1_bytes=$(wc -c < output/第1章-绪论.md)
chN_bytes=$(wc -c < output/第N章-标题.md)
echo "倍率: $(echo "scale=2; $chN_bytes / $ch1_bytes" | bc)"
# 必须 ≥5
```

示例：第1章 = 83KB → 第2章 ≥ 415KB，第3章 ≥ 415KB。

## Mermaid图数量

**每章Mermaid图 ≥ 6张**（第2章实践标准：9张）
- 每张图必须有图号（图N-M）和文字说明
- 无重复图号：`grep -n '图N-'` 逐一验证
- 文字型决策树/流程/时间线/因果链/换算关系必须转为Mermaid图

## 12条写作军规逐项检查清单

每章写完后逐项勾选：

### 0. 体量铁律 □
- 字节数 ≥ 第1章 × (5~10)
- 确认命令：`wc -c output/第N章*.md`
- 若不足，按"补救策略"补充

### 0b. Mermaid图数量 □
- **每章Mermaid图 ≥ 6张**（第2章实践标准：9张）
- 每张图必须有图号（图N-M）和文字说明
- 无重复图号：`grep -n '图N-'` 逐一验证
- 文字型决策树/流程/时间线/因果链/换算关系必须转为Mermaid图

### 0c. 本章总结标题数字一致 □
- 标题写"六个核心要点"则必须恰好6条
- 标题写"七个核心要点"则必须恰好7条
- 验证：`grep -n '核心要点'` 查看标题数字，逐条数表格行

### 1. 详实案例驱动 □
- 每个案例有具体**时间**（年份、月份、日期）
- 每个案例有具体**地点**（厂家名称、产品型号、测试场所）
- 每个案例有具体**数字**（dB值、kHz/MHz频率、成本金额）
- 每个案例有完成的技术**分析**（原因、机理、解决措施）

### 2. 历史极致细节 □
- 组织全称含英文缩写（如 CISPR）
- 具体日期（年-月-日）
- 里程碑事件的意义

### 3. 系统清晰结构 □
- 章首有**内容提要**（1-2段）
- 章首有**学习目标**（7条，可验证动词开头）
- **学习目标覆盖**：逐条核对正文是否提供了学生回答每条目标所需的全部内容
  - 目标说"掌握换算"→正文必须有例题
  - 目标说"理解概念"→正文必须有定义+案例
  - 缺一条覆盖 → 正文内容不足
- 重要概念有**对比表**（≥5个维度）
- 多子主题有**Mermaid总览图**

### 4. 四阶段演进脉络 □
- 时序内容分解为2-3个阶段
- 每阶段有阶段名+起止年份
- 国际和国内双线叙述
- 最后有对照表

### 5. 从现象到概念 □
- 每节从日常现象或工程场景引入
- 引入后给出正式定义
- 定义后有深度案例递进

### 6. 工程实用导向 □
- 每个研究内容配工程场景
- 有具体措施和参数
- 配工程计算或选择原则

### 7. 大篇幅讲细讲透 □
- 每子节≥40KB（核心子节）
- 每子节有实质性展开（≥5段深度分析）

### 8. 含数字实例 □
- 每节有具体数字计算（不是抽象公式）
- 每个公式后有例题（"例 N-N：...解：..."）

### 9. 多标准并列定义 □
- 核心概念引用 ≥2个标准定义
- 引用标准给出全称和编号
- 最后归纳共同点

### 10. 概念对比表 □
- 易混淆概念有对比表
- 对比维度 ≥5条
- 维度名称是直接对立面

### 11. 三级案例结构 □
- 每个案例有**经过**（何时何地发生了什么）
- 每个案例有**分析**（技术原因、机理）
- 每个案例有**启示**（教训、设计原则）

### 12. 教学设问过渡 □
- 大节之间（## → ##）有设问/因果过渡
- 小节之间（### → ###）有递进/转折
- 过渡词交替使用（不全是"下面介绍"）

## 常见体量不足的补救策略

按以下优先级补充内容：

1. **加案例**：每个概念配一个工程案例（三段式，约500-2000字）
2. **加对比表**：把文字描述转为多维对比表（5-8个维度）
3. **加公式推导**：给公式加推导过程（从物理直观到数学形式）
4. **加数字例题**：每个公式后配2个例题（含具体数字计算）
5. **加多标准并列定义**：核心概念引用3-4个标准定义
6. **加历史细节**：给时间线加具体日期、组织全称
7. **加子主题展开**：在主要子主题下加更细分的子子主题
