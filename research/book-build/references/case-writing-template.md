# 案例编写模板（8大模块）

## Overview

EMC教材案例是独立于正文的高完整度技术文档文件，每个案例覆盖从工程背景到验证测试的完整闭环。目标体量 **1200~1800行 / 50~70KB / 30~60公式**。

## 8大模块结构

| # | 模块 | 行数参考 | 核心要素 |
|:-:|:-----|:--------:|:---------|
| 1 | **工程背景** | ~150行 | 产品参数表(20+行)、适用标准与限值表、测试配置说明、环境条件 |
| 2 | **测试数据与诊断** | ~150行 | 故障分级表(≥10行)、放电路径/测试流程Mermaid图、可能根因清单(3-5个带评分) |
| 3 | **根因分析** | ~350行 | 3-4个根因逐一分析、每个根因含六步推导(物理原理→建模假设→原始方程→数学代入→导出结果→参数解释)、根因确认(对消实验/仿真) |
| 4 | **解决方案设计** | ~250行 | 方案1+方案2(含选型表、器件参数表、Mermaid拓扑图、对比表) |
| 5 | **验证测试** | ~200行 | 方案1/方案2/联合方案三组验证数据表(≥10频点)、Mermaid对比图(3个graph LR)、改善量汇总表 |
| 6 | **工程经验** | ~100行 | 5+条设计规则、成本-时机曲线、教材章节对照表、方法论总结 |
| 7 | **拓展应用** | ~80行 | 3个场景变体(不同频率/功率/标准) |
| 8 | **思考题与参考文献** | ~100行 | 5层练习(基础→计算→分析→设计→拓展)、15+篇参考文献/标准 |

## 命名规范

- 按教材章节编号: `案例{章}-{序号}_{中文描述}.md`
- 例: `案例2-1_通信设备辐射发射超标事件.md`、`案例2-2_医疗监护仪静电放电故障.md`
- 公式编号从上一案例末尾延续（如案例2-1结束于2-56，案例2-2从2-57开始）

## 公式要求

- 每个显示公式用 `$$...$$` 包裹（禁止单行 `$$inline$$`）
- `\\tag{N-M}` 独占一行，在 `$$` 块内部、闭合 `$$` 之前
- 每个公式有"式中"逐变量解释
- 六步推导结构（物理原理→建模假设→原始方程→数学代入→导出结果→参数解释）
- 禁止 `\\lg`（用 `\\log`）、`\\left`/`\\right` 必须成对

## 公式编号跨文件延续

当同一章有多个案例文件时，编号必须连续不重叠。案例2-1公式结束于2-56，则案例2-2从2-57开始。

**计算偏移并重排：**
```python
import re
with open('案例2-2.md', 'r') as f:
    c = f.read()
# 假设clean_formula_numbers.py已输出2-1~2-N
c = re.sub(r'\\tag\{2-(\d+)\}', lambda m: f'\\tag{{2-{int(m.group(1))+56}}}', c)
with open('案例2-2.md', 'w') as f:
    f.write(c)
```

**批量修复流程（写完多个案例后统一执行）：**
1. 对每个文件运行 `clean_formula_numbers.py` → 输出 `章-序号` 格式
2. 计算每个文件的起始偏移：上一个文件最后编号 + 1
3. 用 `re.sub` 整体偏移
4. 验证无重复：`python3 -c "import re; tags=re.findall(r'\\\\tag\{\d+-\d+\}', open('f.md').read()); print(len(tags)==len(set(tags)))"`

## 子代理写作约束（铁律——缺此步骤=事后重写）

由于 `delegate_task` 的子代理经常写出无 `$$` 包裹的公式和外部 `\\tag{}`，在子代理的 `context` 中必须**显式包含**以下整段约束：

```text
## 铁律格式约束（不遵守=文件重写）
1. 每个显示公式必须用 $$...$$ 包裹，\\tag{} 必须在 $$ 的内部
2. 禁止单行 $$inline$$ 格式——每个公式独立占多行：$$ \\n 公式内容 \\n \\tag{N-N} \\n $$
3. 公式编号从 \\tag{2-XXX} 开始编号（给具体值）
4. 禁止任何 [[wikilink]]
5. Mermaid 节点标签中禁止 emoji（用"通过/超标/良好"替代）
6. Mermaid 图禁止使用 subgraph（subgraph 标题含特殊字符导致 Obsidian 词法崩溃）
7. 所有图表后加 *图N-X：描述* 或 *表N-X：描述*
8. 公式后必须有"式中"变量解释
9. 使用第三人称学术叙事，禁止第二人称"你"
10. Mermaid 使用 graph LR 或 flowchart TD（最可靠的 Obsidian 类型）
```

## Mermaid规范

- 使用 `graph LR` 或 `flowchart TD`（禁止 xychart-beta）
- subgraph 标题禁止括号/破折号/逗号
- 节点标签禁止 emoji（用"超限值/通过"代替）
- 标签含逗号/括号时用 `["label"]` 包裹
- 每张图后有文字说明

## 质量审查

```bash
python3 scripts/post_generation_check.py output/案例X-Y_*.md --fix --verbose
```

常见问题：
- 子代理写的 `\tag{}` 在 `$$` 外部 → `clean_formula_numbers.py` 清空重排
- 公式缺 `$$` 包裹 → 结构性修复需手动补
- 编号与上一案例重叠 → `python3 -c` 偏移重排
