# 教授级教学法目录（Teaching Methodologies Catalog）

> 域无关的教授级教材写作方法/套路/技巧/质量标准。
> 写作大纲中引用本目录中的方法，填充域相关的具体要求。

## 一、开篇三法（Opening Methods）

每节必须从以下三种方式中选择一种开篇，**禁止直接给出定义或引用标准条文**。

### 1.1 日常现象引入法
- **手法**：从≥2个读者可亲身复现的生活场景切入，建立直觉认知
- **结构**：场景A + 场景B → "这些现象背后指向的是同一个问题——XXX" → 正式内容
- **示例**：手机干扰音箱（人人经历过）→ 引出电磁干扰概念
- **适用场景**：基本概念定义、与日常生活紧密相关的技术

### 1.2 历史震撼事件引入法
- **手法**：1个震撼性的真实工程事故/事件，含时间地点后果，制造认知冲击
- **结构**：事件描述（时间/地点/后果）→ "这起事故的根因是什么？" → 技术分析 → 引出本章主题
- **示例**：丰田刹车门900万辆召回 → 引出"为什么EMC设计如此重要"
- **适用场景**：需强调重要性或安全性的内容

### 1.3 工程矛盾引入法
- **手法**：1个读者已知知识范围内的工程矛盾或技术困境，激发求知欲
- **结构**：已知的工程需求 → "但是...遇到一个问题" → 矛盾分析 → "如何解决？" → 引出解决方案
- **示例**：手机要更薄（天线空间受限）→ 但天线效率必须保证 → 引出电磁兼容设计挑战
- **适用场景**：设计方法、技术方案类内容

## 二、概念建构四步法（Four-Step Concept Building）

每个核心概念的建构必须走四步，**缺一不可**：

| 步骤 | 内容 | 示例 |
|:-----|:-----|:-----|
| **Step 1：现象** | 从具体现象或场景出发，让读者"看到"问题 | "打开电视机时，旁边的日光灯会瞬间变暗" |
| **Step 2：定义** | 给出精准的学术定义，引用权威标准 | "根据GB/T 4365，电磁骚扰是指..." |
| **Step 3：辨析** | 与易混概念对比，配**≥8维对比辨析表** | EMD vs EMI：本质/因果/消除方式/物理量/标准来源/时间/能量/实例 |
| **Step 4：深化** | 在更高层面（系统/工程/应用）深化概念理解 | "系统内EMC与系统间EMC的分层分析" |

**对比辨析表模板**（8维度）：

| 对比维度 | 概念A | 概念B |
|:--------|:-----|:-----|
| **本质** |  |  |
| **因果角色** |  |  |
| **消除方式** |  |  |
| **物理量描述** |  |  |
| **标准来源** |  |  |
| **时间关系** |  |  |
| **能量关系** |  |  |
| **典型实例** |  |  |

## 三、案例三段式（Three-Part Case Structure）

每个案例必须包含三段，**不可缺省**：

```
[背景] 公司名 + 时间 + 地点 + 设备型号 + 关键技术参数（≥3个具体数值）
    ↓
[技术分析] 用已学概念（三要素模型/公式/原理）解释发生了什么，给出定量分析
    ↓
[工程启示] 这个案例教会工程师什么，可操作、可迁移的教训
```

**案例质量底线**：
- 每节≥2个案例（1个生活化 + 1个工程背景），全章≥10个
- 必须来自公开报道真实事件，禁止从参考教材摘抄
- 技术参数至少3个具体数值（频率/电压/距离/金额/数量等）

## 四、数学建模递进法（Mathematical Modeling Progression）

核心公式的推导必须走五步：

```
物理原理 → 建模假设 → 数学代入 → 导出结果 → 参数解释
```

| 步骤 | 内容 | 示例（分贝公式） |
|:-----|:-----|:----------------|
| **① 物理原理** | 说明公式背后的物理定律或基本原理 | "分贝最初定义为功率比的对数" |
| **② 建模假设** | 明确推导的前提和简化假设 | "在相同阻抗Z下，P = V²/Z" |
| **③ 数学代入** | 将假设代入基本公式，逐步代数变换 | "dB = 10 log(P₁/P₂) = 20 log(V₁/V₂)" |
| **④ 导出结果** | 得到最终工程可用公式 | "电压分贝：dB = 20 log(V₁/V₂)" |
| **⑤ 参数解释** | 解释公式中各符号的物理含义和单位 | "V₁、V₂为电压值，单位V" |
| **标注** | `\tag{章-序号}` 独占一行在 `$$` 闭合前 | `\tag{1-2}` |

辅助公式直接给出不自创编号。

## 五、知识结构可视化法（Knowledge Structure Visualization）

| 内容类型 | 推荐图示 | 要求 |
|:---------|:---------|:-----|
| 因果/分类关系 | Mermaid `graph LR` | 白底黑字，节点用双引号，换行用`<br>` |
| 发展历程 | Mermaid `graph LR`（时间线） | 关键节点含日期+事件 |
| 系统层次 | Mermaid `graph LR`（层级展开） | 保证横向≤6列 |
| 数据对比 | Markdown表格 | 表头上方加`**表X-X：标题**` |
| 关系对比 | 对比辨析表（≥8维度） | 如§二所述 |

**Mermaid铁律**：
- 仅 `graph TD` 或 `graph LR`，**优先 `graph LR`**（横向排列）
- 禁止：`timeline` / `mindmap` / `%%{init}%%` / `<-->` / `subgraph` / emoji / 书名号《》
- 节点标签用双引号包裹：`A["标签文字"]`
- 换行用 `<br>` 不是 `\n`
- 每个Mermaid图下方必须有 `*图X-X：标题*` + 3~8句详细解释段落

## 六、脚手架教学四要素（Scaffolding Four Elements）

每节必须嵌入以下四个教学要素（至少各1处）：

| 要素 | 句式示例 | 作用 |
|:-----|:---------|:-----|
| **设问引导句** | "为什么要区分这两个概念？""为什么一个电吹风会导致6万美元罚款？" | 在节开头或关键概念前设问，激发思考 |
| **工程直觉提示** | "值得注意的是...""关键在于...""工程启示告诉我们..." | 标记重点，帮读者建立工程直觉 |
| **教学视角句** | "读者可能已经注意到...""初学时不必纠结于...""在学习中你可能会困惑..." | 站在读者角度，降低认知负担 |
| **前后呼应句** | "这一概念与第X章的XX技术直接相关""将在第X章深入讨论" | 建立章节间知识链接，形成体系认知 |

## 七、多源融合法（Multi-Source Fusion）

写作时采用"三维借鉴"而非"单一抄袭"：

```
教材A的引入手法（日常现象）
    + 教材B的概念辨析深度（对比表维度）
    + 教材C的工程案例视角（实用导向）
    = 融合后的原创教材内容
```

**标注方式**：在写作指南中每要素标注来源：`路宏敏§X.X / 张亮§X.X / 柯金良§X.X / 梁振光§X.X`

**禁止**：
- ❌ 从某一本教材直接复制整段内容
- ❌ 仅把多本教材拼接在一起
- ❌ 案例从参考教材摘抄

## 八、习题三层级（Three-Level Exercise Design）

| 层级 | 特征 | 数量（全章） | 示例 |
|:-----|:-----|:------------|:-----|
| **基础题** | 概念理解、定义复述、术语辨析 | 3~5题 | "请用自己的话解释EMD与EMI的区别" |
| **进阶题** | 结合实际场景的计算和分析 | 3~4题 | "计算某系统的兼容裕度" |
| **思考题** | 开放式、无标准答案的综合问题 | 2~3题 | "如果你是某项目的EMC工程师，请设计方案..." |

## 九、章末四件套（End-of-Chapter Requirements）

| 板块 | 最低要求 | 格式 |
|:-----|:---------|:-----|
| **本章总结** | Mermaid知识结构图 + 6~9个核心要点表格 | 每个要点含：关键内容 + 对应公式编号 + 对应章节 |
| **习题** | 基础(3~5) + 进阶(3~4) + 思考(2~3) = 8~12题 | 每题标注所属节号 |
| **参考文献** | ≥10篇 | 含参考教材、行业标准、公开报告、学术论文 |
| **深入阅读** | 3~6本 | 每本附50~100字推荐理由，适合什么阶段读者 |
