# 写作模式规范（12条军规）



以下12条写作规范从三本书中提炼，每章每节写作时必须逐一遵守。

### 军规1：概念必须先实例后定义

**规则**：给出任何专业定义之前，必须先用大量具体实例让读者建立感性认识。不允许"抽象定义先行"。

```
❌ 错误写法：
"电磁干扰（EMI）是指电磁骚扰引起的设备传输通道或系统性能的下降。"

✅ 正确写法（第2章2.1.1示例）：
"在EMC学科发展的早期，问题解决法几乎是唯一可行的方法。20世纪50年代之前，
电磁兼容尚未形成独立学科，工程界对EMC的认识主要来源于无线电干扰排除的实践经验。
在发达国家，问题解决法从无线电技术诞生一直延续到20世纪50年代。即使在今天，
我国许多制造厂商——特别是中小规模的电子企业——仍然普遍采用这种方法。造成
这一现状的原因是多方面的：产品开发周期短、EMC专业人才匮乏……"
```

### 军规2：每个案例必须有五要素

**规则**：任何工程案例或历史事件的描述，必须同时包含以下五个要素，缺一不可：

```
① 具体年份（含月份/日期更佳）
② 组织全称（含英文名称，首次出现时标注）
③ 具体数字（频率、幅度、距离、温度等量化参数）
④ 事件经过（不少于3-5句话的叙述）
⑤ 事件意义（"这一事件表明……"的分析句）
```

### 军规3：历史事件必须用"详实式"而非"概括式"

```
❌ 概括式（禁止）：
"1933年CISPR成立。"
"1996年欧盟强制执行EMC指令。"
"1966年我国发布第一个EMC标准。"

✅ 详实式（强制）：
"1933年，国际无线电干扰特别委员会（CISPR——Comité International Spécial des
Perturbations Radioélectriques）在法国巴黎成立。CISPR的第一次会议于1934年
6月28日至30日在巴黎召开，提出了两个核心问题：一是'可以接受的无线电干扰限值
是多少'，二是'如何测量无线电干扰'。"
```

### 军规4：设计方法必须用"三阶段对比"

**规则**：介绍任何设计方法或技术路线时，必须按"演进三阶段"结构组织，并使用对比表收束。

```
标准结构：
问题解决法（第一阶段）→ 规范法（第二阶段）→ 系统法（第三阶段）

每阶段的写法：
- 历史背景（什么年代、谁在用、为什么在当时是合理的）
- 核心逻辑（该方法的基本思路和工作流程）
- 优点（至少2条，说明该方法为什么能解决上一阶段的不足）
- 缺点（至少2条，说明该方法为什么会被下一阶段取代）
- 工程案例（1-2个具体数值或场景，展示该方法在实践中的应用）

收束：三阶段对比表（≥7个对比维度）
```

### 军规5：研究内容必须分"狭义/广义"

**规则**：介绍学科的研究领域或技术分类时，必须先区分"狭义概念"和"广义概念"，然后用编号分类逐项详述。

```
标准结构：
第一段：从狭义概念出发，围绕核心框架（如三要素）展开
第二段：从广义概念出发，扩展到跨学科的系统工程
第三段起：用编号（① ② ③ ……）逐项列出具体领域
每项写法：
  ① 领域名称——核心问题描述（1-2句）+ 原理说明（2-3句）+ 工程场景（1-2句）
```

### 军规6：对比表不少于5个维度

**规则**：所有对比表（概念对比、方法对比、类型对比等）的对比维度不得少于5个，最佳为7-8个。

```
标准对比维度模板（按需裁剪）：
本质 / 核心逻辑 / 介入时机 / 适用条件 / 优缺点 / 典型事例 / 成本特性
```

### 军规7：术语必须梳理"因果链"

**规则**：介绍术语体系时，必须梳理术语之间的因果关系，用"→"符号串联，并在段落末尾用一句话概括。

```
标准写法：
"电磁噪声→无用信号→电磁骚扰→（耦合途径）→电磁干扰→（需要）→电磁兼容"

然后在段末加入："用一句话概括这些术语之间的因果关系：______。"
```

### 军规8：数据必须有具体数值

**规则**：在技术描述中，不允许写"较高""较低""很大""很小"等定性描述，必须给出具体的数值或量级。

```
❌ 禁止："静电放电的上升时间非常短，峰值电流很大。"
✅ 强制："ESD脉冲的上升时间在亚纳秒量级（典型值<1ns），峰值电流可达数十安培，
频谱能量分布在几十MHz到几百MHz范围。"
```

### 军规9：习题必须标注学习目标和章节来源

**规则**：每道习题末尾必须标注 `（对应学习目标X，§N.N.N节）`。

```
格式：
N-1 题目内容……（对应学习目标X，§N.N节）
```

### 军规10：公式必须有"式中"解释

**规则**：每个工程公式之后，必须有"式中"段落，对公式中的每个符号做详细解释（含义+单位）。

```
标准格式：
$$
公式 \tag{N-N}
$$

式中，$P_r$ 为接收功率（W），$P_t$ 为发射功率（W），$G_t$ 为发射天线增益（无量纲），
$G_r$ 为接收天线增益（无量纲），$\lambda$ 为工作波长（m），$R$ 为收发距离（m）。
```

### 军规11：分贝换算必须覆盖"定义→换算→公式→例题→速查表"全链条

**规则**：所有涉及分贝（dB）的内容，必须按以下全链条展开：

```
① 数学定义（功率比和电压比的公式，含推导说明）
② 便利性解释（至少2个为什么用dB的理由）
③ 常用绝对单位列表（dBW、dBm、dBμV、dBμV/m、dBμA等）
④ 单位换算公式（P_dBm = P_dBW + 30, U_dBμV = U_dBV + 120）
⑤ 50Ω系统电压-功率换算（U_dBμV = P_dBm + 107，含推导）
⑥ 例题（至少2个，带"解："步骤）
⑦ 速查表（常用比值如2:1、10:1、100:1对应的dB值）
```

### 军规12：频谱知识必须配9频段表

**规则**：涉及电磁波频谱的内容，必须按9个频段逐一列出（ELF/VLF/LF/MF/HF/VHF/UHF/SHF/EHF），每个频段标注频率范围、波长范围和EMC工程关注重点。

### 3.1 概念/定义类（§N.1 常见）

**三段式结构**：

```
[引言段落] 1段
  → 为什么需要这个概念？从前面内容自然引出。
  → 用切身相关的例子或场景拉近概念与读者的距离。
  
[正式定义] 1-3段
  → 先给一个通俗的直观理解，再给正式定义。
  → 如有多个标准定义（GB/T、IEC、IEEE、GJB），并列呈现。
  → 提取所有定义的共同核心要素。
  
[深化理解] 多个段落
  → 分解概念的各要素，逐一解释。
  → 嵌入具体实例（含数字、时间、地点等可验证细节）。
  → 用对比表或关系表收束。
```

**必须包含的元素**：
- [ ] 至少一个生活类比或直观引入
- [ ] 正式定义（引用标准来源）
- [ ] 至少两个标准的定义并列（如有）
- [ ] 实例分析（不是抽象"例如"，而是有具体细节的例子）
- [ ] 对比表或关系表（≥5个对比维度）

### 3.2 要素/框架类（如三要素、三阶段）

**四段式结构**：

```
[引出] → 为什么这个框架重要？解决了什么问题？
[罗列] → 列出各要素，每个要素单独一段解释
[数学模型] → 如有定量关系，给出公式 + "式中"变量解释
[应用验证] → 用表格分析多个实例，展示框架的实用性
```

**必须包含的元素**：
- [ ] 框架的动机说明（为什么需要这个框架）
- [ ] 各要素的详细解释（不是一句话带过）
- [ ] 数学模型或形式化描述（如有）
- [ ] 多个实例的分析表（≥4行）

### 3.3 历史类（§N.2 常见）

**分阶段 + 双线叙事**：

```
[引言] → 为什么了解历史重要？引出时间跨度。

[阶段一：名称（起止年份）]
  → 关键事件逐项列出，每项含：年份 + 事件 + 意义
  → 在关键里程碑处加分析：为什么这个事件重要？

[阶段二：名称（起止年份）]
  → 同上

[阶段三：名称（起止年份）]
  → 同上

[阶段四：国内发展]
  → 分时间线列出国内关键事件

[收束] → 国际/国内对照表
```

**必须包含的元素**：
- [ ] 2-4个发展阶段，每阶段有名有年份
- [ ] 国际发展详写（≥3个阶段）
- [ ] 国内发展单列一节
- [ ] Mermaid时间线图
- [ ] 国际/国内对照表
- [ ] 在关键节点处解释"为什么这是里程碑"

### 3.4 研究内容综述类（§N.3 常见）

**狭义/广义区分 + 编号列举**：

```
[引言] → 为什么要从两个层面理解？整体概览。

[狭义概念] → 围绕三要素的核心技术研究。

[广义概念] → 扩展到多学科交叉的系统工程。

[具体领域]
  → 以编号（① 标题—— 一段解释）形式逐一简介
  → 每项1-3段，内容包括：核心问题、与三要素的关系、所属学科

[收束表] → 可选：研究内容映射表
```

**必须包含的元素**：
- [ ] 狭义概念的解释
- [ ] 广义概念的解释
- [ ] ≥5个编号研究领域
- [ ] 每个领域至少1段有实质内容的说明

### 3.5 特点归纳类（§N.4 常见）

**枚举型结构**：

```
[引言] → 为什么总结特点对学习有帮助？

[特点一：标题]
  → 1-2段解释。包含：具体说明 + 对学习者的意义。

[特点二：标题]
  → 同上。

...（所有特点逐一写出）

[特殊要点] → 如分贝这类工程工具，需要全链条深度处理：
   定义 → 便利性 → 换算表 → 公式 → 例题 → 速查表
   并指向后续章节的详细讨论。
```

**必须包含的元素**：
- [ ] 所有大纲列出的特点（不得遗漏，不得擅自增减顺序）
- [ ] 每个特点有实质性解释（≥1段）
- [ ] 涉及工程工具的（如dB），给定义+换算+例题全链条
- [ ] 涉及跨章内容的，做"后向预告"（详见第X章）
