> v45.1 审计期间的系统性评估。回答"能否不人工干预跑完整本书"。

## 结论

**不能。离全自动约 70%。** 瓶颈在 Phase 2（YAML 生成），其他 10 个阶段已全自动。

## Phase 2 为什么是瓶颈

### 1. "三标准过滤"是纯判断

容器是否升格为"核心概念"取决于：
- 篇幅 ≥ 50 行
- 支撑材料 ≥ 3 个（公式+图+表）
- 有展开结构（子标题或多段落）

不满足的降级为 KE。判断需要理解教材的语义结构，不是正则匹配。

### 2. "定义句必须"规则极其严格

定义句必须：① 前 120 字含标记词 ② 正文连续纯文本子串 ③ 标点引号与原文完全一致。
Agent 不能用自己的话总结——必须从原文逐字复制。错一个字就被闸门拦截。

### 3. 质量闸门会反复拦截

典型失败模式：
- 定义句与原文标点不一致
- 公式引用归属错误（跨概念污染）
- 图片引用被多个概念共享
- wikilink 指向不存在的文件

每次失败需要重新读源文→修正→重试，形成迭代循环。

## 缺失的关键能力

| 能力 | 现状 | 影响 |
|------|------|------|
| 批量章模式 | `-c N` 单章 | 8 章书需人工执行 8 次 |
| 自动章发现 | 手动指定章节号 | 无法遍历 `20_正文/` |
| 自动 YAML 生成 | 无 LLM 管道 | Agent 手动读→判→写 |
| 自动重试循环 | 闸门 FAIL→blocked | 无 fix→retry 机制 |
| 跨章并行 | CLI 不支持 | 8 章不能并行处理 |
| 习题-解答配对 | 文件名推导 | 格式偏差就匹配失败 |

## 实现全自动所需的工作

```
Phase 2 自动化 = LLM 管道
  读 chapter_toc.json (容器行号)
  → 逐容器精读源文 (read_file offset)
  → LLM 判断三标准 + 提取定义句 + 识别 KE/实体
  → 写 YAML (yaml_gen.py extract 获取骨架)
  → 立即 build + content-check
  → 失败 → LLM 读错误日志 + 修正 → 重试 (最多 3 次)
  → 通过 → 下一容器

批量编排器
  pipeline auto --all-chapters (遍历 20_正文/第*章*)
  → 逐章 Phase 2 + pipeline auto
  → 全章完成后 → L2/L3/L4 索引
  支持 --from-chapter N (断点续传)
```

## 当前能做到什么

Agent 可以逐章手动完成 Phase 2，然后 `pipeline auto` 接管一切。
8 章书全部手工完成约需 Agent 持续工作 **2-4 小时**。
