# Scenario Content Spec (应用场景内容生成指南)

场景（Scene）是知识点和技能点在真实工程环境中的综合应用。**场景必须在已有 KP + SP 的基础上生成**。

---

## 两步生成流程（Two-Step Scene Generation）

场景生成采用「骨架→血肉」两步法，禁止一步到位裸写。

### Step A：骨架 — 确定支撑 KP/SP、场景要素与 Bloom 层级

1. **精读源文章节**：`read_file(20_正文/第N章.md, offset, limit)` 定位场景对应的源文容器，记录节标题及其行号范围。
2. **提取支撑 KP 清单**：遍历 `40_知识点/` 目录，锁定本场景将使用的 ≥2 个 KP，输出「支撑 KP 候选表」（Markdown 表格：KP名称/所属节/行号/选用理由）。
3. **提取支撑 SP 清单**：遍历 `50_技能点/` 目录，锁定本场景将使用的 ≥2 个 SP，输出「支撑 SP 候选表」。
4. **拉取关联概念与 KE**：遍历 `30_核心概念/` 和 `30_知识要素/` 目录，确认本场景依赖的 ≥2 个概念和 ≥1 个 KE（含 wikilink），输出「关联概念与 KE 清单」。
5. **识别场景要素**：从源文中提取——干扰源清单、敏感设备清单、耦合路径分析、工程约束条件（≥4 个要素，含至少 3 个具体工程约束参数如成本/尺寸/频率/限值）。
6. **判定 Bloom 层级**：场景通常为「分析→评价」或「分析→评价→创造」，写出层级判定理由（≥80字）。
7. **综合自检**：确认支撑 KP/SP/概念/KE 均存在（文件可检索到），确认 wikilink 路径正确。不满足则 blocked，修正后重来。

### Step B：血肉 — 逐字段精写

1. 基于 Step A 的骨架，按字段填充规则表逐个字段写入，**每字段标注源文容器行号**。
2. 写 `scenario_description` 时，必须明确场景背景（含 ≥3 个具体工程参数）和目标（≥150字）。
3. 写 `workflow_diagram` 时，流程图必须 **≥8 个节点且含分支判断**（如 `{条件判断?}` 菱形节点），Mermaid graph TD/LR 格式。
4. 写 `workflow_analysis`（各节点工作描述）时，流程图中每个节点必须有一句话工作描述，**禁止为"无"**。
5. 写 `typical_application_cases`（方案详解）时，必须含 **≥4 个分项**的详细工程方案，每个分项含：具体器件选型/参数/工程计算，末尾含 **定量预期结果**（如预期裕量/性能指标/成本）。
6. 写 `related_scenes` 时，必须为 ≥3 行的 Markdown 表格，含场景名称/wikilink/关联类型/关联说明。
7. 写 `confusion_scenario_compare` 时，必须含 ≥1 组对比（Markdown 表格或段落），**禁止为"无"**。
8. 所有 `source_from` 精确到 `§节号 L起始行-结束行`，不可仅写节号。
9. 写完所有字段后，立即执行「关联一致性」验证（见下文）。

## 源文精读要求

生成每个场景**之前**，Agent 必须执行以下精读流程：

```
read_file("20_正文/第N章.md", offset=<容器起始行>, limit=<容器长度>)
```

**精读输出的最低标准：**

| 维度 | 要求 |
|:-----|:-----|
| 源文定位 | 明确该场景对应的源文容器节号（如 §4.1） |
| 行级引用 | `source_from` 精确到 `§4.1 L95-214`，不可仅写 `§4` |
| 关键数据提取 | 从源文中提取 ≥3 个具体工程参数（频率/尺寸/成本/限值/裕量），记录原始数据和行号 |
| 工程要素识别 | 明确干扰源类型、敏感设备类型、耦合途径、约束条件 |
| 图示引用 | 若源文含图（图N-M），在工作流程图参考中注明图号 |

**禁止行为：**
- ❌ 不读源文凭记忆写内容
- ❌ `source_from` 仅写节号不写行号
- ❌ 关键数字/参数为幻觉编造
- ❌ 工作流程图为通用模板而非基于源文推导

## 内容深度自检（Scene Content Depth Checklist）

每写完一个场景，必须逐项自检以下 3 条强制标准。**任一条不满足，该场景不可 proceed**：

| # | 自检项 | 通过条件 | 验证方式 |
|:--|:-------|:---------|:---------|
| 1 | 具体性 — 工程约束参数 | 正文含 ≥3 个工程约束参数（具体数值：成本如 BOM<¥50/增加<5%、尺寸如 100×80mm/300×200×80mm、频率如 100kHz/400MHz、标准限值如 CISPR 32 Class A、裕量如 >6dB/>10dB、温升/效率等） | 手动计数场景描述中出现的数字+单位组合 |
| 2 | 源文行号精度 | `source_from` 精确到 `§节号 L起始-结束行`，且行号范围与 `read_file` 结果一致 | 交叉对照 read_file 输出 |
| 3 | 完整性 — 工作流程图 + 方案详解 | (a) 工作流程图 ≥8 节点且含 ≥1 个分支判断菱形节点；(b) 每个节点有工作描述（`workflow_analysis`/`node_descriptions` 不为"无"）；(c) 方案详解 ≥4 个分项，每分项含具体参数/选型/工程计算；(d) 方案详解末尾含定量预期结果 | 手动计数节点数、分项数，检索判断节点 `{.*}` 语法，确认 node_descriptions 不为"无" |

**补充自检（推荐）：**

- [ ] `scenario_description` 含 ≥3 个具体工程参数的数值描述
- [ ] 工作流程图使用 Mermaid graph TD/LR 格式，节点使用中文描述
- [ ] 方案详解中 ≥2 个分项含具体器件型号（如 TPS7A49、Murata DLW5BTN）
- [ ] `related_scenes` 表格 ≥3 行
- [ ] `confusion_scenario_compare` 含 ≥1 组对比，不为"无"
- [ ] 知识脉络图 ≥8 节点，含 `classDef` 颜色编码
- [ ] wikilink 总数 ≥8 条，覆盖 KP/SP/概念/KE 四类

## 关联一致性（Association Consistency）

写完全部场景字段后，**立即**跑 wikilink 验证：

### 验证流程

1. **KP wikilink 校验**：遍历 `core_knowledge_support` 中每个 wikilink，用 `search_files` 验证目标 `.md` 文件存在于 `40_知识点/`。
2. **SP wikilink 校验**：遍历 `core_skill_support` 中每个 wikilink，验证目标文件存在于 `50_技能点/`。
3. **概念 wikilink 校验**：遍历 `scene_concept_support` 中每个 wikilink，验证目标文件存在于 `30_核心概念/`。
4. **KE wikilink 校验**：遍历 `scene_ke_support` 中每个 wikilink，验证目标文件存在于 `30_知识要素/`。
5. **关联场景校验**：遍历 `related_scenes` 表中每个 wikilink，验证目标文件存在于 `70_应用场景/`。

### 阻断规则

```
if any wikilink is 断链 (broken link):
    → BLOCKED: 不可 proceed
    → 修正 wikilink 路径 或 删除该引用
    → 重新验证直到全部通过
```

### 验证结果记录

每完成一个场景的验证，在生成日志中记录：

```
[wikilink 验证] Scene: 电子产品EMC设计全流程
  core_knowledge_support (3/3): ✅ 接地设计与地线干扰抑制 ✅ 屏蔽原理与屏蔽效能分析 ✅ EMI滤波技术原理与应用
  core_skill_support (2/2): ✅ 屏蔽体材料选择与结构设计 ✅ 电源端口EMI滤波器选型与整改
  scene_concept_support (2/2): ✅ 电场屏蔽 ✅ PCB电磁兼容设计方法
  scene_ke_support (4/4): ✅ 接地技术概述 ✅ 屏蔽效能 ✅ 共模干扰 ✅ 地环路干扰
  related_scenes (3/3): ✅ ...
```

## 字段填充规则

| 模板变量 | 内容要求 | 必须填？ | 来源 |
|---------|---------|:-------:|:----:|
| `name` | 场景名称 | **必需** | — |
| `bloom_level` | 布鲁姆认知层级（通常为"分析→评价"或"分析→评价→创造"） | **必需** | 推理 |
| `bloom_level_description` | 层级解读——Bloom 层级的详细解释（≥150字） | **必需** | 推理 |
| `bloom_progression` | 认知递进链——Mermaid graph LR 5 节点图 | **必需** | 自主生成 |
| `bloom_progression_analysis` | 认知跃迁解析——5 层递进解析（≥150字） | **必需** | 自主生成 |
| `bloom_alignment` | Bloom 对齐矩阵——5 行 Markdown 表格 | **必需** | 自主生成 |
| `scenario_type` | 场景类型（如设计场景/测试场景/仿真场景/综合工程应用等） | **必需** | 推理 |
| `scenario_description` | 场景目标——该场景要解决什么问题/达成什么目标（≥150字，含≥3个具体工程参数） | **必需** | 推理 |
| `domain` | 所属领域 | **必需** | — |
| `scene_elements` | 场景要素——构成该场景的关键元素（≥4 项，含说明：干扰源/敏感设备/耦合路径/约束条件） | **必需** | 推理 |
| `constraints` | 物理环境/电磁环境——该场景的环境条件和技术约束（≥100字） | **必需** | 推理 |
| `technical_environment` | 技术环境/系统组成——该场景的技术栈和系统架构（≥100字） | **必需** | 推理 |
| `boundary_conditions` | 边界条件——该场景的适用范围（≥3 条） | **必需** | 推理 |
| `core_knowledge_support` | 支撑知识点——该场景调用的 KP wikilink（≥2 条，含说明） | **必需** | KP |
| `core_skill_support` | 支撑技能点——该场景调用的 SP wikilink（≥2 条，含说明） | **必需** | SP |
| `scene_concept_support` | 支撑概念——该场景引用的概念 wikilink（≥2 条） | **必需** | 概念 |
| `scene_ke_support` | 支撑知识要素——该场景使用的 KE wikilink（≥1 条），无则填"无" | 推荐 | KE |
| `workflow_diagram` | 工作流程图——Mermaid graph TD/LR 流程图，≥8 个节点，**必须含 ≥1 个分支判断菱形节点** `{条件?}` | **必需** | 自主生成 |
| `node_descriptions` | 各节点工作描述——逐节点一句话描述其工作内容，覆盖流程图中每个节点，**禁止为"无"** | **必需** | 自主生成 |
| `workflow_analysis` | 案例操作流程说明——逐 Step 说明流程，每 Step 含参数+动作+理论依据（≥4 个 Step） | **必需** | 自主生成 |
| `typical_application_cases` | 典型应用案例——方案详解，≥4 个分项（含具体器件参数/选型/工程计算），末尾含**定量预期结果**（如裕量/性能指标/成本） | **必需** | 推理 |
| `related_scenes` | 关联场景——同类/上下游场景的对比表格（≥3 行，Markdown 表格，含 wikilink），**禁止为"无"** | **必需** | 推理 |
| `confusion_scenario_compare` | 易混淆辨析——与其他场景的对比（≥1 组），**禁止为"无"** | **必需** | 推理 |
| `evolution` | 发展演进——该场景的发展趋势，无则填"无" | 推荐 | 推理 |
| `knowledge_context_diagram` | 知识脉络图——Mermaid graph TD 图，展示场景与 KP/SP/关联场景的关联（≥8 个节点，含 classDef 颜色编码） | **必需** | 自主生成 |
| `diagram_analysis` | 知识脉络图解析——逐节点解析图中含义（≥5 段） | **必需** | 自主生成 |

## 内容质量标准

| 标准 | 通过条件 |
|:-----|:---------|
| Bloom 字段完整性 | bloom_level_description/递进链/对齐矩阵/认知解析均不可为无或空 |
| 场景描述完整性 | scenario_description ≥150字，domain 不可为无 |
| 场景要素 ≥4 | scene_elements 含干扰源/敏感设备/耦合路径/约束条件 |
| 工程约束参数 ≥3 | scenario_description + scene_elements 中至少出现 3 个具体数值参数 |
| 文件大小 | ≥8KB |
| 工作流程图 | ≥8 节点 + ≥1 个分支判断 |
| 节点描述 | 每个节点有描述，node_descriptions 不为"无" |
| 方案详解 | ≥4 个分项 + 定量预期结果 |
| Mermaid 图 | 3 张（工作流程图≥8节点 + 认知递进链5节点 + 知识脉络图≥8节点） |
| 关联场景表格 | ≥3 行 |
| 易混淆辨析 | ≥1 组 |
| wikilink 引用 | ≥8 条 |

## 依赖关系

生成前必须确认：
- [ ] 该场景涉及的 KP 文件已存在
- [ ] 该场景涉及的 SP 文件已存在
- [ ] 该场景涉及的核心概念文件已存在
- [ ] 该场景涉及的 KE 文件已存在（若有）
- [ ] 所有 wikilink 指向真实存在的文件
