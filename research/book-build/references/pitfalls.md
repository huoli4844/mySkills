# Pitfalls 完整陷阱列表

| # | 陷阱 | 预防 |
|:-:|:-----|:-----|
| 1 | **添加大纲不存在的章节** | 大纲之外一律不写 |
| 2 | **遗漏大纲存在的章节** | 写作后逐项对照大纲检查 |
| 3 | **直接复制KB模板结构** | KB是原料，教材是成品，必须二次加工 |
| 4 | **公式用Unicode非LaTeX** | md 用 `$$`，docx 用 OMML XML |
| 5 | **使用显性教学步骤标记** | 用第三人称学术叙事替代 |
| 6 | **第二人称"你"用于正文叙事** | 正文用第三人称（"读者""人们"） |
| 7 | **刻意拆短段落** | 真实教材使用100-300字信息密集型长段落 |
| 8 | **每个案例末尾用显性「EMC启示：」标记** | 案例的分析和启示应自然融入叙事 |
| 9 | **等长段落** | 核心段10+行，辅助段3-5行，结论单句段 |
| 10 | **过渡词单一** | 交替使用设问/类比/递进/转折/因果 |
| 11 | **每节同一结构** | 先判断内容类型（6种模式之一）再选结构 |
| 12 | **习题只有概念题** | 每章必须包含概念/简答/计算/分析各一 |
| 13 | **docx公式不可编辑** | 验证：`assert '<m:oMath' in raw_bytes` |
| 14 | **KB零结果时留空** | 即使零素材也要基于通用知识写出来 |
| 15 | **verify_chapter 的 summary 计数** | 脚本用 `^\d+\.` 匹配总结条目 |
| 16 | **大纲是.docx格式未先提取** | 用 `file2md` 或 `parse_outline.py` 预处理 |
| 17 | **Obsidian Mermaid 图太小** | 加 `%%{init: {"flowchart": {"useMaxWidth": false}}}%%` |
| 18 | **本章总结只有文字没有图** | 必须图文并茂——Mermaid图+要点表格 |
| 19 | **忽视三书共同盲区分析** | 系统分析每本书没写透的内容是独创价值所在 |
| 20 | **某本书主题不匹配却硬套** | 只借鉴写作手法，内容从其他来源补充 |
| 21 | **文字型决策树未转Mermaid图** | 所有决策树/时间线/因果链须转为Mermaid图 |
| 22 | **图号冲突** | 添加Mermaid图后用 `grep -n '图N-'` 验证 |
| 23 | **临时文件未清理** | 章组装完成后 `rm -f` 清理 section-*.md |
| 24 | **本章总结标题数字与实际条数不一致** | `grep -n '核心要点'` 检查标题数字 |

## 硬件相关 Pitfalls

| # | 陷阱 | 说明 | 正确做法 |
|:-:|:-----|:-----|:---------|
| 25 | **Mermaid mindmap 崩溃** | >100节点或含emoji导致Obsidian渲染崩溃 | ≤30节点，不用emoji |
| 26 | **`\`\`{init}` JSON 语法** | 单引号或缺失闭合 `%%` 导致Error | 双引号JSON+闭合`%%` |
| 27 | **YAML 多行 Mermaid** | `\n`转义在yaml.safe_load中不识别 | 用 `|` block scalar |
| 28 | **公式 \left/\right 不匹配** | ```\left(``` 无 ```\right)``` → 渲染失败 | 每个 `\left` 必须配对 `\right` |
