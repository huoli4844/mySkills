# 知识点模板 v7.0 设计

> 从学生视角重构 KP 模板。v6→v7。

## 动机

v6.0 模板存在三个问题：
1. 学生打开页面先看到 Bloom 元数据（认知层级/学习目标/对齐矩阵），而非"这个东西能干什么"
2. "无"节被自动删除，同类型文件结构不一致
3. 缺少学生自测、踩坑辨析、工程实践等学习闭环

## 新结构 (v7.0)

```
# 知识点名称
> 🎯 学完能做什么  |  ⏱️ 约 30 分钟

一、核心讲解    (理论→推导→细节→KE清单)
二、动手实践    (例题→方法→场景→工程要点→踩坑辨析)
三、知识地图    (关联网络 Mermaid 图 + 解析)
四、认知进阶    (Bloom五件套 + 能力要求)
五、自学检验    (2-4道自测题)
```

## 变更统计

| 操作 | 数量 | 详情 |
|:--|:--|:--|
| 新增 | 3 节 | 工程实践要点、踩坑辨析、自学检验 |
| 删除 | 4 节 | 知识点名称(冗余)、前置概念(空)、所属领域(重复)、典型考题与辨析(重叠) |
| 合并 | 3 组 | 技能要求+目标→能力要求(表格)、4个关联子节→关联知识网络、5个Bloom子节→认知进阶 |
| 移动 | — | Bloom从开头→第四节认知进阶 |

## 关键设计决策

1. **不区分"教师区/学生区"**：统一模板，Bloom在第四节自然融入学习路径
2. **空节保留**：`_strip_wu_sections` 禁用，所有文件结构完全一致
3. **HTML注释指导Agent**：每个 `{{field}}` 后跟注释说明字数/格式/示例
4. **quality_score 联动**：新增字段加入 `REQUIRED_BD_FIELDS` 和 `_WU_FORBIDDEN_PATTERNS`，字数阈值纳入 `_FIELD_WORD_THRESHOLDS`
